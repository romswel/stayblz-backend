# Stayblz email templates

Branded templates for Supabase Auth emails. Generated by `node scripts/build-email-templates.cjs`.
Edit the script, not the HTML files, then rebuild. The script refuses to build if a code-only
template gains a confirm/reset link or loses the code.

## Files to paste (Supabase → Authentication → Emails → Templates)

| Supabase template | Subject (paste from) | Message body (paste from) |
| --- | --- | --- |
| Confirm signup | `confirm-signup.subject.txt` | `confirm-signup.html` |
| Reset password | `reset-password.subject.txt` | `reset-password.html` |
| Invite user | `invite.subject.txt` | `invite.html` |
| Change email address | `change-email.subject.txt` | `change-email.html` |

- **Confirm signup** and **Reset password** are **code-only**: a 6-digit code (`{{ .Token }}`) and no
  button. People type the code on the sign-up screen or the "Reset your password" screen.
  Mail scanners that open links can no longer use up the code.
- The sign-up email keeps one link, **"This wasn't me"** (`/auth/not-me`). It can't sign anyone in:
  it opens a page that asks before removing an unconfirmed sign-up made with that address.
- `confirm-signup.txt` and `reset-password.txt` are plain-text versions. Supabase's template editor
  only takes HTML, so these are for reference (or a future custom email sender); the HTML is written so
  the code still reads correctly in text-only mail apps.
- `with-links/` holds the earlier sign-up and reset templates (code **and** a button). Paste those back
  to switch the button on again. The app still accepts those links (`/auth/confirm`), so emails already
  sent keep working either way.

## Supabase settings these templates rely on

1. **Authentication → URL Configuration**
   - Site URL: `https://stayblz-app.com` (the "This wasn't me" link and the invite/email-change
     buttons use `{{ .SiteURL }}`).
   - Redirect URLs: `https://stayblz-app.com/auth/confirm`, `https://stayblz-app.com/auth/confirm?recovery=1`,
     and for local testing `http://localhost:5173/auth/confirm`. Remove `https://stayblz-frontend.vercel.app/**`.
2. **Authentication → Providers → Email**
   - Confirm email: **on**.
   - Email OTP Length: **6** (the app accepts exactly 6 digits).
   - Email OTP Expiration: **3600** seconds. The emails say "expires in 1 hour"; if you change this,
     change `CODE_LIFETIME` in the script and rebuild.
3. **Authentication → Emails → SMTP Settings** (Resend)
   - Sender email: an address on the verified domain, for example `no-reply@stayblz-app.com`.
   - Sender name: `Stayblz`.
   - Host `smtp.resend.com`, port 465 (or 587), username `resend`, password = a Resend API key
     with sending access only. Never put the key in this repository.
4. Send yourself a test sign-up and a password reset. Check the code works, the sender shows as
   Stayblz, and the message isn't in spam.
